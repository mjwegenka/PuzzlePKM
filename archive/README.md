## Why These Exist

These files represent earlier design iterations, experimental features, or automation experiments that were evaluated and either completed, replaced, or deprioritized. Keeping them in an archive allows:

1. **Historical reference** — Understanding how the project evolved
2. **Avoiding duplication** — New contributors know to look at current canonical docs instead
3. **Backup context** — If a feature is reconsidered, the old design thinking is preserved

## When to Use Archived Files

**Do not use archived files as reference unless:**
1. You need to understand historical decisions (migration planning, legacy compatibility)
2. You are implementing a feature that was previously attempted and documented
3. You need context for why something was deprecated

**Always reference the canonical files instead** for current guidance.
